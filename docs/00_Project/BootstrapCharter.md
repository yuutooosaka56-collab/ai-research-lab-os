# Bootstrap Charter

- **Status:** Draft
- **Version:** 0.1
- **Decision horizon:** Pre-MVP
- **Review trigger:** MVP評価完了時

## 1. Purpose of This Charter

本書はAI研究室OSの恒久的なMissionを決定するものではない。正式な存在理由を検討できる最小実験環境を構築するため、開発中の暫定目的・範囲・判断基準を定める。

## 2. Problem Statement

単体の生成AIは複雑な問いに回答できるが、以下の課題がある。

- 調査、反証、統合の品質が依頼方法に依存する
- 根拠・仮説・推測の区別が不安定である
- 結論に至った設計判断を再利用しにくい
- 同一モデルが提案・批判・採点を兼任し、独立性が弱い
- 複数AIの利用が品質向上につながったか客観評価しにくい

## 3. Bootstrap Objective

複雑な問いに対し、複数のAIまたは複数の役割が、調査・反証・統合を再現可能な手順で実行し、単体AIより高品質で検証可能な回答を生成できるかを実験する。

## 4. Initial User

初期利用者はプロジェクトオーナー本人とする。第三者向けサービス、一般公開UI、複数ユーザー管理はMVPの対象外とする。

## 5. MVP Scope

MVPは以下の3役を基本構成とする。

### Researcher

- 問いを分解する
- 前提条件と重要論点を整理する
- 根拠候補と情報不足を示す

### Skeptic

- 論理の穴を検出する
- 反証・代替仮説を提示する
- 根拠の品質と過剰な確信を批判する

### Synthesizer

- ResearcherとSkepticの出力を統合する
- 事実、推論、仮説を区別する
- 確信度、不確実性、次の検証行動を示す

## 6. Out of Scope

Bootstrap段階では以下を作らない。

- 9種類以上の固定エージェント群
- 自律的な無制限討論
- 本番用RAG・ベクトルDB
- 長期記憶の完全実装
- 高度な権限管理
- 商用課金
- モバイルアプリ
- 独自LLMの学習

## 7. Provisional Success Criteria

最低限、以下を満たした場合にMVPを評価対象とする。

1. 同一質問を単体AIとOS構成で比較できる
2. 各役割の入出力が保存される
3. 根拠、反証、結論、不確実性が分離される
4. トークン量、概算費用、処理時間を記録できる
5. 事前定義した評価基準で比較できる
6. 処理回数に明示的な上限がある

## 8. Decision Principles

- 真実らしさより検証可能性を優先する
- AIの多数決を証拠として扱わない
- 必要性が示されるまでエージェントを追加しない
- 複雑性、費用、遅延を品質と同時に評価する
- 最終的な設計判断は人間が行う
- 重要な判断と変更理由はADRに記録する

## 9. Formal Mission Review

MVP完成後、以下の議題をAI研究室OS自身で検討する。

> AI研究室OSは何のために存在するべきか。

その結果と単体AIの回答を比較し、正式なMission、Vision、AI憲法、ロードマップを決定する。

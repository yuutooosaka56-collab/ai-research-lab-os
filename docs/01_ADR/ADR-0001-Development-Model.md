# ADR-0001: Development Model

- **Status:** Accepted provisionally
- **Date:** 2026-08-03
- **Decision owners:** Project owner

## Context

AI研究室OSは、思想・研究プロトコル・ソフトウェア設計・実装・評価を含む。単一AIに全工程を任せると、そのAI固有の盲点、自作自演評価、ベンダー依存が強くなる。一方、常時複数AIを動かすと費用と複雑性が急増する。

## Decision

BootstrapおよびMVP段階では、以下の役割分担を採用する。

### Human Project Owner

- 目的、優先順位、予算、リスク許容度を決定する
- 重要なADRを承認する
- 最終的な採否責任を持つ

### ChatGPT

- 要件整理
- アーキテクチャ設計
- 設計書の統合と整合性確認
- 調査と総合レビュー
- GitHub上の文書・Issue・PR管理支援

### Claude / Claude Code

- 独立した批判的レビュー
- リポジトリ全体を用いた実装
- テスト、リファクタリング、バグ修正
- ChatGPT案への反証

## Operating Rules

1. 重要設計は一方のAI出力だけで確定しない
2. 毎回すべてを二重実行しない
3. 高コストな相互レビューは重要変更に限定する
4. 共通の仕様書、評価基準、GitHubリポジトリを唯一の正式情報源とする
5. AI同士の不一致は隠さず、ADRまたはIssueに記録する
6. 実装能力は実際のMVPタスクで再評価する

## Consequences

### Positive

- 設計と実装の得意領域を分担できる
- 独立レビューによって盲点を減らせる
- どちらか一社への完全依存を緩和できる
- プロジェクト文脈をGitHubに固定できる

### Negative

- 利用料金と管理負担が増える
- モデル間で用語・設計解釈がずれる
- 同じ変更を二重に処理する危険がある
- 最終調整役が必要になる

## Alternatives Considered

### ChatGPTのみ

運用は単純だが、独立レビューと実装比較が弱くなる。

### Claudeのみ

コード実装には強い可能性があるが、既存のプロジェクト文脈移行と全体統括で追加負担がある。

### 常時全AIを並列実行

比較可能性は高いが、費用・遅延・重複が大きく、Bootstrap方針に反する。

## Review Trigger

以下のいずれかで本ADRを再検討する。

- MVP実装完了
- 主要モデルの変更
- 月間AI費用が予算上限を超える
- 実装品質または保守性に明確な差が出る
